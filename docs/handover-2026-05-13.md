## 9. Recurring Workflow Traps (encountered in this session)

These traps recurred multiple times in the 13 May 2026 session. Mitigate proactively:

### Trap 1: PowerShell in System32
PowerShell windows sometimes open in System32. Always `cd C:\Users\morri\signal-cleanup\Signal` before git operations.

### Trap 2: `git checkout -b` failing silently
If a local branch with the target name already exists, `git checkout -b feat/X` fails with `fatal: a branch named 'feat/X' already exists`. The error is easy to miss. Subsequent edits and commits then land on main.
**Mitigation:** ALWAYS run `git status` immediately after `git checkout -b` to verify the new branch is actually active. Recurred 3 times in single session.

### Trap 3: Files not in Downloads
When Claude presents files via `present_files`, they appear as tappable cards in chat. Chris must click each card to actually download to `C:\Users\morri\Downloads\`. Files aren't auto-downloaded.

### Trap 4: PowerShell parsing `<` and `>`
PowerShell interprets `<` as redirection. Don't paste output containing PowerShell brackets into the terminal.

### Trap 5: Browser automation drag-and-drop incompatible with @dnd-kit
`@dnd-kit/core`'s PointerSensor relies on a stream of `pointermove` events. Browser automation tools (Playwright `dragTo`, agent `left_click_drag`) don't reliably emit these. Drops register on the source droppable instead of the target.
**Mitigation:** Drive drag-and-drop state via test API (`window.__signalSortAndMatchTestApi.placePhrase(...)`), not real drag automation. Manual mouse testing only for visual verification.

### Trap 6: Squash-merge warning on `git branch -d` is NOT proof of merge
The "merged to refs/remotes/origin/X but not merged to HEAD" warning only confirms local matches origin tracking ref. Only `git pull --ff-only origin main` showing a fast-forward arrow with file diff, OR direct PR status on GitHub, confirms actual merge.

### Trap 7: Wrong-branch commit (new PowerShell window defaults to main)
Opening a new PowerShell window for a parallel task (e.g., running vitest while emulator runs in first window) starts on whatever HEAD currently is — main if no branch set. Commits made in that window go to main, not the feature branch.
**Mitigation:** `git status` first in every new window before any git operation. If on wrong branch, recovery: cherry-pick the commit onto the feat branch, then reset main back to origin/main, then push feat.

### Trap 8: Pasting secrets in chat
Recurred 3 times in single session (Testing, Ccjm1982-u65, Testing again). Pattern matters more than specific values.
**Mitigation:** Set env vars via `.env` file (gitignored) and a loader script, OR keep credentials in Notepad and type into PowerShell manually. Never paste `$env:VAR = "..."` assignments into chat.

## 10. Key Engineering Learnings (from memory)

### Firebase / architecture
- `firestore.ts` uses module imports (`import { app, auth } from "../firebase"`), NOT `window.MSM_APP` legacy pattern.
- Risk Classifier route is `/content-areas/risk-classifier` (NOT `/risk-classifier`). Page at `src/pages/content-areas/risk-classifier.astro`.
- The `if (!app) return null` graceful bailout in Firestore wrappers is a high-risk silent-failure pattern — always verify persistence is actually writing.

### Testing
- vitest + `@firebase/rules-unit-testing`: each test file MUST use a unique `projectId` in `initializeTestEnvironment`. Shared projectId causes race where files clobber each other's rules. Pattern: `risk-classifier.test.ts` → `"demo-signal-rules"`, `sort-and-match.test.ts` → `"demo-signal-sort-and-match-rules"`.
- Always remind to run vitest locally (`npx vitest run path/to/test.ts`) before pushing PRs that touch *.test.ts or pure logic files with test counterparts.

### GitHub API encoding
- ALWAYS use TextDecoder when reading GitHub API base64 content. Never `atob()` directly as string (returns latin-1, corrupts multi-byte chars including ®, —, emojis).

### TypeScript
- `useRef<TYPE>` generic argument MUST be on same line as `useRef` in `.tsx` files. Multi-line form makes parser interpret `<` as JSX.

### npm
- When adding a new dependency locally, always commit both `package.json` AND `package-lock.json` in the same PR. CI runs `npm ci` (strict) and refuses if files are out of sync.

### CSS
- `landing.css` and `global.css` serve different page contexts and don't share cascade. Apparent "duplicate" token declarations across both files are intentional page-scoping, NOT dedupe targets. Verify which pages load each stylesheet before deduping any token.

### PowerShell / encoding
- PS 5.1 reads script files as Windows-1252 by default. Keep PS scripts ASCII-only.
- `Set-Content -Encoding UTF8` writes BOM by default. Firestore rules compiler rejects BOM. Use `[System.IO.File]::WriteAllText(path, content, [System.Text.UTF8Encoding]::new($false))` to write without BOM.

### GitHub Actions
- **Sync-with-main pattern (scoped):** In any GitHub Actions workflow whose final step is `git push origin main` (typically `workflow_dispatch` jobs writing to main), add a "Sync with latest remote main" step immediately after checkout: `git fetch origin main && git merge origin/main --ff-only`. **DO NOT apply to `pull_request` workflows, feature-branch workflows, or read-only workflows.**
- All Python patch scripts embedded in workflows: base64-encode to avoid YAML parsing failures.
