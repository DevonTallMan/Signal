### Stacked PRs after squash-merge

When PR B is stacked on PR A and A squash-merges to main, B's branch gets `CONFLICTING` even though the diff is conceptually clean. Fix:

```powershell
git checkout <PR-B-branch>
git fetch origin
git rebase origin/main   # Git detects A's commit was already applied via squash; skips it cleanly
git push --force-with-lease origin <PR-B-branch>
```

Pattern verified twice in this project: Twin Tracks 4.3 stacked on 4.2, then methodological re-agreement #97 stacked on #96. Each rebase took under 30 seconds.

Chris has authorized force-push to feature branches for this specific pattern. Each occurrence still warrants a one-line confirmation in chat before doing it.

## 9. Recurring Workflow Traps

Encountered multiple times across sessions. Mitigate proactively.

**Trap 1: PowerShell in System32.** New PS windows sometimes open in System32. Always `cd C:\Users\morri\signal-cleanup\Signal` first. Or use full paths in `npm --prefix C:\Users\morri\signal-cleanup\Signal ...`.

**Trap 2: `git checkout -b` failing silently.** If a local branch with the target name already exists, the command fails with `fatal: a branch named 'feat/X' already exists`. Subsequent edits and commits then land on the wrong branch. **MITIGATION: ALWAYS run `git status` immediately after `git checkout -b` to verify the new branch is active.** Recurred during Sprint 4 Inc 4.3.

**Trap 3: Files in chat aren't auto-downloaded.** When files are presented as cards, Chris must click each card.

**Trap 4: PowerShell parsing `<` and `>`.** Don't paste output containing PS brackets into the terminal.

**Trap 5: `@dnd-kit/core` drag automation incompatible with Playwright.** PointerSensor needs a stream of pointermove events; browser automation drops fail. **MITIGATION: drive drag-and-drop in tests via test API (`window.__signalSortAndMatchTestApi`, `window.__signalTwinTracksTestApi`), never real drag automation. Manual mouse only for visual verification.**

**Trap 6: `git branch -d` "merged to origin" warning is NOT proof of merge.** Only `git pull --ff-only origin main` showing a fast-forward arrow with file diff, OR direct PR status on GitHub, confirms actual merge.

**Trap 7: Wrong-branch commit in new PowerShell window.** New PS window starts on whatever HEAD is. **MITIGATION: `git status` first in every new window.** Recovery: cherry-pick onto feat branch, reset main back to origin/main, push feat.

**Trap 8: Pasting secrets in chat.** Use `.env` plus loader script, OR keep credentials in Notepad and type into PS manually. Never paste `$env:VAR = "..."` assignments into chat.

**Trap 9 (new, 2026-05-14): YAML colon parsing in mdoc frontmatter.** Strings containing `keyword: value` patterns are parsed as YAML mappings. Quote the string to avoid: `- "Recognise the most common cause of lost Explain marks: scenario tie-back missing or superficial"`. Surfaced during m-3-1 authoring.

**Trap 10 (new, 2026-05-14): Markdoc inline tags must not start a line at column 0.** A `{% role %}` opening tag at the start of a line gets parsed as block-level regardless of the `inline: true` schema flag. Always have prose precede the tag on the same line. Surfaced during the m-2-1 legend authoring on PR #88.

## 10. Key Engineering Learnings

### Firebase / architecture
- `firestore.ts` uses module imports (`import { app, auth } from "../firebase"`), NOT legacy `window.MSM_APP` pattern.
- Activity route convention: `/content-areas/{activity-slug}`.
- The `if (!app) return null` graceful bailout in Firestore wrappers is a HIGH-RISK silent-failure pattern. Always verify persistence is actually writing.

### Testing
- vitest + `@firebase/rules-unit-testing`: each test file MUST use a unique `projectId`. Current values:
  - `risk-classifier.test.ts` → `"demo-signal-rules"`
  - `sort-and-match.test.ts` → `"demo-signal-sort-and-match-rules"`
  - `twin-tracks.test.ts` → `"demo-signal-twin-tracks-rules"`
- Always run vitest locally (`npx vitest run path/to/test.ts`) before pushing PRs that touch `*.test.ts` or pure logic files with test counterparts.

### Status lifecycle CI check
- `scripts/check-status-lifecycle.mjs` enforces three rules on published topics:
  - R1: published topic must have ≥1 reviewer
  - R2: published topic must have `last_reviewed` set
  - R3: content body / assessments / learning_outcomes change on a published topic requires `last_reviewed` bump
- The check runs in CI as the "Status lifecycle" check. Failed in PR #88; fixed by bumping `last_reviewed` on both m-1-1 and m-2-1.

### GitHub API encoding
- ALWAYS use TextDecoder when reading GitHub API base64 content. Never `atob()` directly as string.

### TypeScript / TSX
- `useRef<TYPE>` generic argument MUST be on same line as `useRef` in `.tsx` files.
- Template literal types work for typed enums of composite IDs: `type CellId = \`${Track}-${Slot}\`` (used in Twin Tracks).

### npm
- When adding a new dependency locally, always commit both `package.json` AND `package-lock.json` in the same PR.

### CSS
- `landing.css` and `global.css` serve different page contexts and don't share cascade.
- The Method/Answer-Arc colour convention is N=green, E=gold, I=#ff9d3a (no `--amber` token; the Impact accent uses an inline hex per repo convention).
- The cyberpunk landing nav uses `// COMMENT` style kickers (`// CORE PAPER ONE`, `// WHAT THIS DRILLS`). Don't introduce em-dashes there.

### PowerShell / encoding
- PS 5.1 reads script files as Windows-1252 by default. Keep PS scripts ASCII-only.
- `Set-Content -Encoding UTF8` writes BOM by default. Firestore rules compiler rejects BOM. Use `[System.IO.File]::WriteAllText(path, content, [System.Text.UTF8Encoding]::new($false))`.

### GitHub Actions
- Sync-with-main pattern (scoped): in any workflow whose final step is `git push origin main`, add a "Sync with latest remote main" step. DO NOT apply to `pull_request` workflows or feature-branch workflows.
- Python patch scripts embedded in workflows: base64-encode to avoid YAML parsing failures.
