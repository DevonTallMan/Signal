## 7. Workflow Conventions

### Standard increment delivery

1. Sync main, cut feat branch (or docs branch for scope/handover docs)
2. Make changes, build, run relevant tests locally
3. Stage specific files (never `-A`)
4. Commit with descriptive message
5. Push, open **draft PR** with thorough body
6. CI runs (6 checks: Cloudflare, Astro schema, Status lifecycle, Assessment ID stability, vitest unit+rules, e2e)
7. Chris reviews branch preview, marks ready, asks to merge
8. Squash merge with PR-numbered commit title

### Stacked PRs

When a feature splits across multiple PRs, prefer waiting for the parent to merge before cutting the child. The PR #127-close-by-mistake earlier today was the cautionary tale. Stacked-then-rebased works fine if the parent merges cleanly; the cost of "wait for green" is small.

### Production rules deploy

**After any firestore.rules change, deploy to BOTH environments per Trap 12:**

```
firebase deploy --only firestore:rules --project signal-staging-26b3e
firebase deploy --only firestore:rules --project mark-scheme-method-3efe9
```

The next PR's Playwright suite hits staging Firebase and will fail with permission errors if staging is stale.

## 8. Recurring Workflow Traps

Numbered list preserved across sessions.

**Trap 1: PowerShell in System32.** New PS windows sometimes open in System32. Always `cd C:\Users\morri\signal-cleanup\Signal` first.

**Trap 2: `git checkout -b` failing silently.** Always `git status` immediately after.

**Trap 3: Files in chat aren't auto-downloaded.** Chris must click each card.

**Trap 4: PowerShell parsing `<` and `>` in pasted terminal output.** Don't paste output containing PS brackets into the terminal.

**Trap 5: `@dnd-kit/core` drag automation incompatible with Playwright.** Drive drag-and-drop in tests via test API, never real drag automation.

**Trap 6: `git branch -d` "merged to origin" warning is NOT proof of merge.** Only `git pull --ff-only origin main` showing a fast-forward arrow with file diff, OR direct PR status on GitHub, confirms actual merge.

**Trap 7: Wrong-branch commit in new PowerShell window.** `git status` first in every new window.

**Trap 8: Pasting secrets in chat.** Use `.env` plus loader script, OR keep credentials in Notepad and type into PS manually.

**Trap 9: YAML colon parsing in mdoc frontmatter.** Strings containing `keyword: value` patterns parse as YAML mappings. Quote the string.

**Trap 10: Markdoc inline tags at column 0 parse as block-level.** Even with `inline: true` in the schema. Always have prose precede the tag on the same line. Addendum: inside blockquotes, multi-line patterns are unreliable too; chain role tags inline on a single line.

**Trap 11: PS here-string commit messages with `->`, `<`, `>` fail silently.** Use `git commit -F <file>` for multi-line commit messages.

**Trap 12: Firestore rules deploy must hit BOTH staging and production.** Playwright tests routed to staging fail with permission errors if staging is stale. Two-command deploy after every rules-changing PR merge.

**Trap 13: Playwright `page.clock.install` conflicts with Firebase Auth token validation.** Don't mock the clock. Use the test API's `seedCardWithDueDate`-style methods to plant time-shifted state directly.

**Trap 14: npm-installed CLIs ship `.ps1` shims blocked by PS Restricted execution policy.** Use `.cmd` wrappers (`npm.cmd`, `npx.cmd`, `firebase.cmd`).

**Trap 15 (2026-05-16): Markdoc block-tag content on a single line parses as malformed open.** Block-tag content (`{% def %}content{% /def %}`) must have content on its own lines between opening and closing tokens. Surfaced during Inc 7.0 comic plumbing (#125).

**Trap 16 (2026-05-16): lifecycle check can transient-fail on CI even when local passes.** Re-trigger via empty commit. Cause unclear; possibly npm install race or transient network. The lifecycle and assessment-id-stability checks share a workflow job; if one fails and the other passes on the same run, it is almost certainly transient.

**Trap 17 (2026-05-16): Manual rules-deploy gap blocks Playwright specs that exercise newly-added Firestore collections.** Inc 7B.1 surfaced this. The mcqSubmissions rules block from #138 was in main but not in staging Firestore for several CI runs of #139. Every MCQ Firestore operation returned permission-denied; the runner went to error state; the test timed out. Mitigation patterns:
- For new rules collections that have e2e specs, deploy rules to staging BEFORE merging the PR that introduces the spec.
- OR ship a defensive fallback in the component that falls through to a usable state on read failure (the MCQRunner pattern from #139 commit f86428e).
- OR mark the spec `test.fixme` until deploy confirmed; remove the fixme as part of the deploy-confirmation PR.
- Adding a CI step that auto-deploys rules to staging on PR merge would close this loop. Out of scope for this session; named here as a future infrastructure improvement.

## 9. Key Engineering Learnings

### Firebase / architecture
- `firestore.ts` uses module imports, NOT legacy `window.MSM_APP` pattern.
- Activity route convention: `/content-areas/{activity-slug}`.
- The `if (!app) return null` graceful bailout in Firestore wrappers is a HIGH-RISK silent-failure pattern. Always verify persistence is actually writing.
- Sprint 6 extended `users/{uid}/drillRatings/{compositeId}` rather than creating a parallel collection. compositeId = `${topicId}__${termId}`.
- Sprint 7B added a parallel pattern at `users/{uid}/mcqSubmissions/{compositeId}` where compositeId = `${topicId}__${questionId}`.

### Testing
- vitest + `@firebase/rules-unit-testing`: each test file MUST use a unique `projectId`. Current values:
  - `risk-classifier.test.ts` → `"demo-signal-rules"`
  - `sort-and-match.test.ts` → `"demo-signal-sort-and-match-rules"`
  - `twin-tracks.test.ts` → `"demo-signal-twin-tracks-rules"`
  - `drill-scheduler.test.ts` → `"demo-signal-drill-scheduler-rules"`
  - `teacher-dashboard.test.ts` → `"demo-signal-teacher-dashboard-rules"` (Sprint 7A)
  - `mcq-submissions.test.ts` → `"demo-signal-mcq-rules"` (Sprint 7B/7C)
- For rules tests, the Firestore emulator must be running. CI uses `firebase emulators:exec --only firestore --project demo-test "npm test"`.

### Playwright
- Test isolation for drill-review specs: each run overwrites termA (`411-drill-01`) and termB (`411-drill-02`) on the seeded test user.
- Sort & Match and Twin Tracks full-session specs are robust to any `totalScenarios` value.

### Drill-review timing (Sprint 6 + #124 + #139's two follow-up fixes)
- PR #124 made `getAllCardStates` async so phase=done set synchronously.
- #139 (Inc 7.4 commit chain) added fire-and-forget on the `saveDrillRatingWithScheduler` write too, with a `pendingWritesRef` tracker exposed via the test API so `getCardState` reads await pending writes before reading. Pattern generalises to any future component with fire-and-forget writes + test-API read-backs.
- Test timeouts widened from 5s to 15s across the `revealed`, `cue` and `done` transitions in `tests/drill-review.full-session.spec.ts` for defensive margin against staging Firestore latency.

### TypeScript / TSX
- `useRef<TYPE>` generic argument MUST be on same line as `useRef` in `.tsx` files.

### npm / Node
- When adding a new dependency locally, always commit both `package.json` AND `package-lock.json` in the same PR.

### CSS
- `landing.css` and `global.css` serve different page contexts and don't share cascade.
- Method/Answer-Arc colour convention: N=green (`#39FF14`), E=gold (`#FFD700`), I=`#ff9d3a`.
- Comic palette tokens use `--neon-*` prefix; coexist with `--green` / `--gold` / `--amber`.
- Sprint 7A added a `.teacher` block.
- Sprint 7B added `.mcq-runner` and `.mcq-summary` blocks.

### Markdoc tags
- `{% role name="name|explain|impact" %}` — inline. N·E·I structural highlighting.
- `{% illo panel="scope|regime|actors|principles|lawful-bases|rights" %}` — block. CA 4.1 Data Protection section-break illustrations (PR #117).
- Comic family: `{% panels %}`, `{% panel %}`, `{% takeaway %}`, `{% def %}`, `{% term-card %}`, `{% docs-compare %}`, `{% doc %}`, `{% cloud %}`, `{% chip %}` (inline), `{% closer %}`, `{% step %}`, `{% comic-illo %}`. Used on topics with `display_style: comic` in frontmatter.

### React state during async
- `rate()` and similar handlers that fire-and-forget Firestore writes risk a test-time race where read-back tests see stale Firestore state. The `pendingWritesRef: Set<Promise>` pattern from #139 (drained by test-API reads) generalises.
